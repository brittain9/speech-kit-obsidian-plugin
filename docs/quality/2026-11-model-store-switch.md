# Model store switching

Changing the model store is an explicit Apply action. Typing does not save the path or query the sidecar. The manager checks the new store before saving it, holds the sidecar mutation gate during the switch, clears stale managed-model data, and refreshes the selected speech and read-aloud models in sequence. It preserves model selections and external-file capability snapshots. A failed preflight leaves the old path and list intact.

Managed-model capability snapshots now record the configured store. Older snapshots without a store identity require one fresh probe. This avoids showing a model as ready using capabilities from a different folder.

The three store-scoped sidecar queries now use request IDs. Responses and errors must match the originating request, including after a timeout. The sidecar accepts old requests without IDs and omits the field in their responses. The updated frontend requires a sidecar that echoes the IDs; an older sidecar is rejected with an update message. The frontend and native sidecar must be built and installed together for development testing. A future sidecar-bearing release must update the compatibility pointer under the release process. No release, tag, or version change is included here.

Tests cover explicit Apply, active-work refusal, failed preflight and settings save, stale initialization and probe results, disposal, preserved selections, and out-of-order or late query responses. A locally built sidecar returned matching IDs for two temporary stores, their empty installed lists, and an invalid-path error. It then exited cleanly. Native Obsidian verification passed in the authorized test vault with a matching rebuilt sidecar: editing the path did not save it; an empty store cleared the selected speech model readiness and marked translation unavailable; returning to the default store restored speech readiness, installed translation status, and the selected read-aloud voice. Apply during active listening reported that the engine was busy and preserved the store and capture session. An invalid path beneath a file produced an actionable error and preserved the old store and model readiness. The two public QA notes remained byte-for-byte unchanged, and capture was left off.

The store preflight checks the existing directory or nearest existing parent without modifying files. It rejects non-directory and broken-link paths. It preserves readable, read-only model stores. The preflight does not guarantee write access; installation reports actual write failures. A native test with a file as a parent reproduced the previously accepted invalid path and now returns an error before the setting changes.

The final native QA used the sidecar with SHA-256 `309848bb24f8bd3ae4a505a5c399dde75cecc8ba09ff8005fe1223fc39878f4c`. Its combined frontend also included the optional note-pinning change and passed 1,839 tests with ten skipped, both typechecks, both linters, and the production build. The isolated store branch passed 1,828 frontend tests with ten skipped and the full native gate. These results do not replace the required CI checks.
