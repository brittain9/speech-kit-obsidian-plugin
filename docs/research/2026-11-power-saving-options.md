# Power-saving options for listening and idle resources

Recommendation: measure idle wakeups first. Do not unload an active dictation model after 30 seconds of silence yet. The current code exposes two 10 ms polling loops even when there is no active work. Replacing unnecessary polling with event-driven notification is a narrower candidate, provided measurements show a worthwhile cost and tests preserve event delivery and shutdown. A shorter TTS or translation idle lifetime is a separate memory-versus-reload tradeoff; it does not establish a battery benefit. No energy or CPU measurement was made for this note.

## What the code does

| State                              | Work and retained resources                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Dictation off, sidecar not started | No sidecar worker or microphone capture is running.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Dictation off, sidecar running     | The main stdio loop waits at most 10 ms before draining worker events. The translation worker also waits at most 10 ms, even with no helper. These are up to roughly 100 timeout opportunities per second per loop, not measured OS wakeup or CPU rates. The transcription worker blocks on its command receiver when idle. The synthesis worker blocks indefinitely when its cache is empty. [Main loop](../../native/src/main.rs), [translation worker](../../native/src/translation_worker.rs), [transcription worker](../../native/src/worker.rs), [synthesis worker](../../native/src/synthesis_worker.rs).                                           |
| Listening in silence               | Microphone capture and the audio worklet remain active. The worklet mixes and resamples audio and sends 20 ms PCM frames to the sidecar. The session runs Silero VAD on 512-sample windows at 16 kHz, including silence: about 31.25 inference windows per second of continuous audio. These are code-derived operation counts, not measured utilization. The VAD retains its state and a small onset pre-roll. Streaming audio is sent to the transcription worker only after VAD confirms an utterance; a loaded model therefore does not by itself prove ongoing ASR inference during silence. A normal stop drains accepted utterances before teardown; cancellation has different semantics. | Read-aloud                         | The synthesis worker retains a loaded model for 90 seconds after work, then drops it. While no model is cached it waits without a periodic timeout. [Synthesis worker](../../native/src/synthesis_worker.rs).                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Local translation                  | The isolated HY-MT helper stays for five minutes after a terminal result; cancellation stops it. The translation worker polls at 10 ms even when no helper exists. A new request after expiry starts a helper again. [Translation worker](../../native/src/translation_worker.rs), [helper boundary decision](../adr/0005-use-an-engine-registry-and-isolated-hy-mt-helper.md).                                                                                                                                                                                                                                                                            |

The main loop cannot simply block forever on its input channel: worker events and context deadlines are drained outside that channel. The translation loop similarly polls a separate helper event receiver and checks helper exit and the idle deadline. An event-driven change needs to deliver those signals to the owning loop and retain deadline handling. [App event drain](../../native/src/app.rs), [main loop](../../native/src/main.rs), [translation worker](../../native/src/translation_worker.rs).

Microphone capture, system audio, optional recording, OS scheduling, GPU drivers, runtime threads, and provider activity can add work beyond these paths. Resident memory alone is not evidence of active CPU, power draw, or battery-life impact.

## Constraints on unloading during listening

A 30-second silence timer is feasible in principle, but the current session owns the model continuously. A safe change must retain live capture and VAD, preserve the existing 15-frame onset pre-roll and confirmation frames, and preserve the session clock, VAD state, ordering, transcript context, and streaming utterance boundaries. Stopping capture to save more work cannot guarantee the first words are heard. [Session boundaries](../../native/src/session.rs), [streaming dispatch](../../native/src/app.rs).

On confirmed resumed speech, model load can take longer than an utterance. Audio from the retained pre-roll and all subsequent frames must remain ordered and available until the model is ready. A bounded backlog needs an explicit, visible overload outcome; silent truncation is not acceptable. The existing 30-utterance overload limit is not a bound on all live audio queued during a slow model load. Streaming and batch models need separate checks. A load failure must surface an actionable error without presenting the session as successfully listening.

An unload may occur only after pending finalization and worker operations release the model. Stop must drain accepted speech, including speech queued while reloading. Cancel, restart, disposal, installation, and store changes must fence late loads and unloads by session ownership. A late completion must neither revive a cancelled session nor affect a newer session. Existing model replacement already uses a worker release barrier; any new model lifetime must preserve that proof. [Drain and overload](../../native/src/app.rs), [release barrier](../../native/src/worker.rs).

These requirements add a new asynchronous state machine and memory pressure during slow loads. No observed battery benefit or reload cost currently justifies it. Defer the optional 30-second mode until measurements show that model residency itself is material, and show that resumed-speech latency and backlog behavior are acceptable across supported engines.

## Proposed measurements and tests

1. In the test vault, record hardware, OS, power source, build and model identifiers, audio device and settings. Measure comparable windows after warm-up: plugin disabled; sidecar running with dictation off; active microphone in silence; active speech; immediately after stop; read-aloud idle before and after 90 seconds; translation helper idle before and after five minutes. Repeat in alternating order with other activity held as steady as practical. Record process CPU time, thread wakeups where the OS exposes them, RSS, and GPU activity. Treat them as observations for that machine, not battery-life estimates.
2. If idle loops are material, first prototype event notification. Test that worker results, context deadlines, helper exit, shutdown, and cancellation still reach the host promptly with no traffic. Compare the same idle and active windows and latency distributions against the baseline. Do not change the timer solely from static counts.
3. Before any unload feature, use synthetic VAD and a controllable delayed model loader at the public session boundary. Test 30 seconds of silence then speech with quiet onset, continuous speech longer than load, multiple utterances during load, immediate stop, cancel during load, restart during old load, load failure, and full backlog. Assert exact ordered samples including pre-roll, no duplicate or lost accepted speech, preserved final drain, explicit overload, no stale transcript, and released model ownership. Cover streaming and batch adapters, system audio, and recording separately.
4. With public speech fixtures, run paced native end-to-end tests across representative models and platforms. Measure cold and warm load times, first-partial and final latency, peak backlog and RSS, and repeated stop/restart. Compare text and audio boundaries with the existing always-loaded path. Include slow storage and an intentional loader failure. Test TTL changes independently for TTS and translation, including cancellation and a request at the expiry boundary.

No production changes or battery-life claims follow from this investigation. The existing resource baseline task remains open. [Maintenance log](../quality/autonomous-maintenance-2026-11-log.md).
