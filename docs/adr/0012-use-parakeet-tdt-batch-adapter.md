# Experiment: separate bounded Parakeet TDT batch adapter

Status: experimental, excluded from the managed catalog after natural-long German failed both direct and native VAD tests. This decision records the isolated adapter experiment, not an accepted production backend.

Parakeet TDT v3 introduces multilingual batch recognition and model-derived token timing through a token-and-duration decoder. Keep it separate from the existing English streaming Parakeet Unified RNN-T adapter: their feature graphs, recurrent state, token advancement, and language behavior differ. Reuse the existing local ONNX Runtime, model manager, and native VAD pipeline, with a pinned int8 export and the export's own small feature graph. This avoids a second Python/NeMo or MLX runtime and preserves existing streaming compatibility.

Use CPU execution initially, a 35-second adapter input bound, and existing native VAD's 30-second utterance segmentation for longer recordings. File duration and decoded-memory budgets remain media policy rather than model context limits. Model timestamps are relative to each utterance and must be monotonic and bounded by its audio duration. Automatic recognition is intrinsic to this model; an explicit supported language is validation, not a conditioning prompt or an asserted detected-language result. Initially expose only the eight existing product languages covered by the model (English, Spanish, German, French, Portuguese, Italian, Dutch, Croatian).

The current Open ASR leaderboard supports evaluating this family, but its server/GPU throughput does not predict local performance. Managed catalog inclusion depends on real local fixture quality, timing, resource bounds, cancellation, and installation checks. Keep current defaults unchanged. Reject inconsistent graph shapes or malformed companion files at probe rather than advertising an unstartable model. A failed quality gate leaves the candidate experimental instead of weakening the gate.

Considered alternatives: another Whisper quantization reduces artifact size but does not satisfy the distinct-model request; Granite CTC is plausible but offers less direct timing value for this app; loading NeMo/PyTorch would add a substantially larger runtime and deployment surface. A shared generic transducer framework is deferred until another implementation demonstrates the same stable boundary. Share only existing tokenizer/tensor utilities whose contracts actually match.
